02 · The problem

A government officer can be held in contempt
for a deadline they never knew existed.

When a Karnataka High Court judgment lands in a department's inbox, today's workflow is:

  1. A junior officer reads the order — typically 8–40 pages of dense legal text.
  2. They produce a hand-typed notes sheet — what to do, who must do it, by when.
  3. They forward it to the responsible officer — often by name, not by designation.
  4. Then they hope nothing was missed.

No verification. No audit trail. No way to defend a decision in contempt proceedings.

⚠ Personal liability

The officer named in a contempt petition is the human being, not the department. Officers transfer; pending obligations follow the role, but petitions name the person.

The user is a Deputy Secretary, not a lawyer. The output must survive court scrutiny.

03 · What we built

A staff-assistance compliance engine.
Not a chatbot. Not a legal AI.

The system reads a disposed judgment, returns a verified action plan, and writes every reasoning step to an append-only audit log.

Pipeline
Judgment PDF→ OCR + segment→ Voice tag→ Section classify→ Directive extract→ Rules engine→ Action plan
  • Officer always decides. The system never auto-commits anything.
  • Every field carries a verbatim source span. Click → highlight in PDF.
  • Every action carries a statute citation and the calculation that produced its deadline.
★ The architectural keystone

The LLM never computes deadlines.

The LLM extracts only: paragraph type, verdict class, and offset spans pointing at directive verbs. Every date, every officer designation, every statute citation comes from a deterministic Python rules engine reading versioned YAML rule tables.

if a language model could be wrong about it,
it goes in extraction/.
if it must be exactly right,
it goes in rules_engine/.

05 · Why phantom obligations are structurally impossible

Six independent guards. A fabricated directive can't survive any one of them.

GUARD 01
Section gate

Only paragraphs labelled OPERATIVE ever reach the directive parser. Reasoning, facts, precedent — all filtered upstream.

GUARD 02
Voice gate

Within an OPERATIVE paragraph, every directive's character span is checked: must be COURT voice. Statutory paraphrases and quoted holdings excluded.

GUARD 03
Bounds + substring

The LLM emits offsets only. The verbatim text is reconstructed from paragraph.text[s:e]. A hallucinated paraphrase cannot survive — it has no real offsets.

GUARD 04
Actor FK guard

Each directive's addressee resolves to a respondent number that exists in the case caption. Unresolved → routed to officer review, never auto-assigned.

GUARD 05
Render-time validators

DISMISSED_WITH_OBLIGATION, OBLIGATION_WITHOUT_SOURCE, TARGET_NOT_IN_RESPONDENTS, and three more. Plans with errors don't render.

GUARD 06
Verdict gate at engine

A DISMISSED case with an extracted directive is rejected at the rules engine itself. Verdict + obligations are mutually checked.

Result: the four historical "phantom card" outputs that earlier prompt-engineering versions emitted on Venkateshulu are structurally unconstructible in the current pipeline — verified by tests/test_phantom_cards_unconstructible.py.

07 · The case-type-agnostic core

Same pipeline. Different rule tables.

None of the six pipeline modules are KHC-specific or writ-specific. Cause-title parsing, voice tagging, section classification, directive extraction, rules engine — these all generalise. The only thing that changes per jurisdiction or per case-type is a YAML file.

Stable across all case types
01Cause-title parserparties · designations · dates
02Segmenter + voice taggerCOURT vs quoted vs party
03Section classifierFACTS · REASONING · OPERATIVE…
04Directive extractoroffset spans + actor + verb
05Rules engine + validatorsdeterministic · YAML-driven
Per-jurisdiction · per-case-type

Each YAML cites its statute. Rule version is bumped on every edit. The Python engine doesn't move.

08 · How criminal + civil + writ + tax unify

One engine. All four case-type families.

CIVIL WRIT today · Phase B

Article 226 / 227 of the Constitution

  • Limitation: 90-day SLP under Article 136 (DISMISSED), 30-day review under CPC Order XLVII (ALLOWED)
  • Directive verbs: DIRECT, ORDER, QUASH, REMAND, ISSUE_NOTICE, DISPOSE_WITH_DIRECTION
  • Status: ✓ working end-to-end on real PDF
CRIMINAL APPEAL +1 YAML rule table

Section 374 CrPC · 90-day appeal

  • Limitation: 90 days from sentencing for HC appeals (S. 374(2)); 60 days for SC (Article 134)
  • New directive verbs: CONVICT, SENTENCE, REMAND_TO_CUSTODY, GRANT_BAIL_PENDING_APPEAL
  • Effort: rule table + verb literal addition · same engine
BAIL ORDERS +1 YAML rule table

Section 437 / 439 CrPC

  • Conditions become directives: "report twice weekly", "surrender passport within 7 days"
  • Targets: the accused (designation: "Accused / Petitioner") and the SHO of the police station
  • Compliance check: per-condition deadline tracking
TAX / REVENUE +1 YAML rule table

Section 260A IT Act · 120-day HC appeal

  • Limitation: 120-day HC appeal from ITAT order (S. 260A); 90-day SC appeal under S. 261
  • Directive verbs: ASSESS, REASSESS, REFUND, RECOVER
  • Targets: Commissioner / Assessing Officer (per-jurisdiction designation map)
Pattern: each case-type family adds (a) a YAML rule table with statute citations and (b) directive-verb literals to the existing union. Zero engine changes. Same six guards apply.

Why this scales horizontally

  • The Python engine is jurisdiction-neutral; only YAML rule tables vary by state.
  • Designation maps are per-state YAML; legal-officer designations are stable across departments.
  • The audit log is append-only and partitioned by month — petabyte-scale ready.
  • Every output is contempt-defensible by construction: every field has a verbatim source span.

Adoption story

  • Pilot — one Karnataka department, 3 months, ~5K orders processed.
  • State rollout — all KHC writs flowing into State Data Centre, all departments.
  • National rollout — per-state YAML rule tables, single deployed engine.
  • Open-source rule tables — citizen-auditable statute interpretations.
